# UI引き継ぎメモ

Kotlin / Jetpack Composeの画面だけを担当しています。API、認証、通信形式、AI、データ保存の仕様は決めていません。

## 提案

図書館・201教室などの行き先を選び、場所名つきの室温と金沢の気温を表示。主役は写真付きの服装提案カードです。提案・指数はすべて固定サンプル。温度色は表示上の仮ルールで22℃未満を水色、それ以上をオレンジにしています。GPS取得・不快指数算出・服装判定は実装していません。

## コーデAI

想定する体験は「写真で相談・評価 → コーデを保存 → 履歴と気温・室温に合わせてAIが提案」です。

現在の実装は、チャットの見た目、カメラ起動、写真選択・解除、メッセージ入力、固定サンプル応答、保存ボタンです。応答は実際の評価ではありません。送信・保存・履歴に基づくAI提案は未実装です。カメラは`TakePicturePreview`で表示用サムネイルを取得します。本番の高解像度画像の受け渡し方式は別途決めてください。

## 気温別コーデ

固定サンプル2件に、生成した写真を表示。画像は `drawable-nodpi/outfit_warm.png` と `outfit_cool.png` にあります。実際の利用者の過去の写真ではありません。

絞り込みの「今の金沢」は屋外気温、「今の室温」は選択場所の室温、「温度を指定」は入力した屋外気温を基準に、過去サンプルの対応する温度が±2℃以内のものを表示します。サーバー上の検索処理はありません。

## みんなのひろば

普段は固定の投稿一覧。上部ボタンから投稿シートを開き、場所・体感・コメントを入力できます。投稿ボタンは案内を表示するだけです。フォームは一覧に常駐せず、ボタンもスクロールに追従しません。

## 連携の境界

`UiModels.kt` は表示項目をまとめたデータクラスとサンプルです。サーバー側のJSON形式を指定しません。
`ClimaFitViewModel.kt` の会話一覧は表示確認用のメモリー上の状態です。通信・データ保存はありません。AI・保存・投稿・センサー・天気・GPSの連携方式が決まった後、担当者が各コールバックへ接続してください。
