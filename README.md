# LayeRoom（レイルーム）— 現在の機能一覧

LayeRoomは、外気温だけでは分からない大学の講義室の暑さ・寒さに着目し、快適に過ごすための服選びを支えるアプリです。

現在はKotlin / Jetpack Composeによる**フロントエンドのUIプロトタイプ**です。本READMEに画面・操作・実装範囲をまとめています。データは表示サンプルで、実際のAPI通信・AI処理・保存は実装していません。

## 1. 全体構成

下部タブは、左から次の3つです。

| 左 | 中央 | 右 |
| --- | --- | --- |
| 気温別コーデ | ホーム | 今日のひろば |

- アプリの新規起動時は中央の「ホーム」を表示します。
- AIの専用タブと、以前のAI入口画面は削除しました。ホームから直接機能を使います。
- チャット・AI向けの文章入力欄はありません。
- ベージュ・テラコッタ・水色の配色と、「L」を重ねたアプリアイコンを使用しています。
- ホーム画面用アイコン・起動時・アプリ上部のマークは共通です。
- 温度の表示色は仮のUIルールとして22℃未満を水色、それ以上をオレンジにしています。快適さや服装の判定ロジックではありません。
- 登録場所のサンプルは「図書館」「201教室」「学生食堂」「実験室3」の4つです。

## 2. ホーム

### 今日の服装の目安

上部に「今日の服装の目安」カードを表示します。服の種類を伝えるカードと、右下の具体的なコーデ提案の入口で役割を分けています。

- トップス・ボトムス・羽織りの3行に、それぞれ生成したピクトグラムを添えます。
- Tシャツ、薄手のズボン、薄手のカーディガンなどの服の目安と、短いアドバイスを表示します。
- 選択した場所、金沢の気温、場所の室温、湿度・快適さのサンプル表示。
- 場所を変更すると、その場所用の固定表示サンプルに切り替わります。AI生成や服装判定は行いません。

ピクトグラムは温かみのあるオレンジ・水色・ベージュで統一しています。素材は `app/src/main/res/drawable-nodpi/guide_tshirt.png`、`guide_trousers.png`、`guide_cardigan.png` です。コーデ写真は場所別の提案画面・気温別コーデで引き続き使用します。

### 左下：写真でコーデ診断

1. ホーム左下の「写真でコーデ診断」を押します。
2. **Android標準の写真選択画面を直接開きます。** アプリ独自の中間シートはありません。
3. 写真を**1枚だけ**選ぶと、直後に診断画面へ遷移し、画像を読み込みます。
4. 読み込みが成功したら、フロントエンド内の診断アクションに画像と選択場所の情報を設定します。

- 追加の「診断する」ボタンや確認画面はありません。
- 写真選択画面を閉じたら、そのままホームへ戻れます。
- 写真選択をキャンセルした場合はホームに留まり、診断アクションを作成しません。
- 10MB以下の画像を表示用に縮小して読み込みます。カメラを開く中間メニューは廃止し、写真から直接選ぶ方式です。
- 読み込めない画像ではエラーと「写真を選び直す」を表示し、診断アクションを作成しません。
- 診断画面には、選択画像と診断中の表示サンプルを表示します。実際の送信・AI診断は行っていません。
- 戻る操作や別タブへの移動時は、進行中の画像読込みをキャンセルします。

### 右下：○○のおすすめ

右下カードに「図書館のおすすめ」など、選択場所の名前を表示します。

| 押す部分 | 動作 |
| --- | --- |
| 「図書館」などの場所名 | 下から全登録場所の選択シートを開く |
| 選択シート内の場所 | ホームの選択場所と表示を変更してシートを閉じる。AI提案はまだ実行しない |
| 場所名以外のカード部分 | 固定プロンプトと場所の情報を設定し、そのまま提案画面へ遷移 |

- 固定プロンプトは **`今日の服装を提案して`** です。
- 選択場所・その室温・金沢の気温を、フロントエンド内のアクションに一緒に設定します。
- 場所選択後の追加確認や、遷移先で再度押す提案ボタンはありません。
- 提案画面は、押した時点の場所の名前と気温を表示します。
- 写真付きの提案結果と「このコーデを保存」の表示サンプルがあります。実際のAI送信・生成・保存は行いません。

## 3. 気温別コーデ

以前の機能を維持しています。

### 一覧

- 過去の服装を想定した、写真付きのサンプル2件。
- コーデ名・日付・場所・金沢の気温・室温。
- 実際の利用者の過去の写真や履歴ではありません。

### 絞り込み

| 条件 | 動作 |
| --- | --- |
| すべて | すべてのサンプルを表示 |
| 今の金沢 | 現在の金沢のサンプル気温に近い屋外気温のコーデを表示 |
| 今の室温 | 下に場所のプルダウンを表示し、選択場所の室温に近いコーデを表示 |
| 温度を指定 | 下に数値入力欄を表示し、指定した屋外気温に近いコーデを表示 |

- 過去サンプルの対応する温度が、指定条件の±2℃に入るものを表示します。
- 指定温度の範囲は−50〜60℃です。不正な入力や、一致するコーデがない場合の案内もあります。
- 「今の室温」で選んだ場所は、ホームのおすすめの場所と共通です。
- 絞り込みは画面内のサンプルに対する操作です。サーバー検索は行いません。

## 4. 今日のひろば

### 場所を選んで口コミを見る

1. 右端の「今日のひろば」タブを押します。
2. 下から登録されている全場所の選択シートを開きます。
3. 場所を1つ選ぶと、**その場所の口コミだけ**を一覧表示します。
4. すでにひろばを開いていても、同じタブをもう一度押すとシートを再び開き、場所を選び直せます。

- 一覧内の「場所を変更」ボタンからも選び直せます。
- 未選択のままシートを閉じた場合は、場所の選択案内を表示します。
- すでに選択済みでシートをキャンセルした場合は、以前の場所の口コミを維持します。
- 全口コミサンプルから場所名で絞り込み、件数と口コミを表示します。該当する口コミがない場合は空の案内を表示します。
- 口コミには場所・体感・コメント・時刻を表示します。寒い投稿は水色、暑い投稿はオレンジ、快適な投稿は緑のバッジです。
- ひろばの閲覧場所は、ホーム・気温別コーデの選択場所と独立しています。
- 実際の口コミ取得・サーバー検索は実装していません。

### 投稿フォーム

- 場所を選んだ後、「いまの体感を投稿する」で投稿シートを開きます。
- 場所・体感・ひとことを入力できます。場所は閲覧中の場所を初期表示します。
- コメントは1〜500文字の範囲で投稿ボタンを有効にします。日本語IMEの変換状態を保持します。
- 投稿ボタンは、UIプレビューのため送信・保存しないことを案内するだけです。
- フォームは一覧に常駐せず、投稿ボタンも一覧の下方向へのスクロールに追従しません。

## 5. 実装範囲

| 実装済みのUI | 未実装の処理 |
| --- | --- |
| 3タブ・ホーム初期表示・画面遷移 | 認証・ログイン |
| 標準写真ピッカーの直接起動・1枚選択・自動遷移 | AIへの画像送信・写真評価 |
| 固定プロンプトと場所情報の受け渡し・自動遷移 | AI提案の取得・生成・履歴に基づく推薦 |
| 場所選択・温度や場所による表示の絞り込み | センサー・天気・口コミの取得、サーバー検索 |
| 診断中・提案結果・保存・投稿の表示サンプル | 実際の保存・投稿・データベース・端末間共有 |

- GPSは未実装で、金沢固定です。
- 不快指数・服装提案は固定表示で、計算や判定は行いません。
- 写真や操作結果は実行中のメモリー上で扱い、アプリ終了後には保存しません。
- 操作時の受け渡し先は `LayeRoomViewModel.latestAiRequest` です。写真または固定プロンプト、場所・室温・外気温のスナップショットを設定します。
- サーバーAPIの形式やエンドポイントは定義せず、実際の通信・AI処理・保存はバックエンド側の担当範囲です。

## 6. 起動・更新

1. Android Studioで `settings.gradle.kts` がある **`codex_test` フォルダー**を開きます。
2. **Git → Pull** で `main` を更新します。再クローンは不要です。
3. 必要に応じて **File → Sync Project with Gradle Files** を実行します。
4. 上部で `app` と端末を選び、**▶ Run** を押します。

更新版は **1.8** です。表示名はLayeRoomで、既存アプリへ上書き更新できるよう内部のアプリID・パッケージ名 `jp.climafit.app` は維持しています。

| 構成 | バージョン |
| --- | --- |
| Android Studio | Meerkat以降、Otter 3対応 |
| Gradle / Android Gradle Plugin | 8.11.1 / 8.9.2 |
| Kotlin / Compose BOM | 2.1.20 / 2025.03.01 |
| 最小Android API | 26 |
| compile / target SDK | 35 |

初回同期にはネット接続、JDK 17以上、Android SDK Platform 35が必要です。

## 7. 主なファイルと検証

Kotlinファイルは `app/src/main/java/jp/climafit/app/` にあります。

| ファイル | 役割 |
| --- | --- |
| `MainActivity.kt` | 3タブ、起動時ホーム、写真選択と各画面の遷移 |
| `HomeScreen.kt` | ピクトグラム付きの服装の目安、写真診断・場所別おすすめの左右カード |
| `LocationPickerSheet.kt` | 全登録場所を表示する共通の選択シート |
| `AiStatusScreen.kt` | 写真読み込み・エラー・診断中・提案の表示サンプル |
| `OutfitScreens.kt` | 既存の気温別コーデ一覧・温度条件の絞り込み |
| `CommunityScreen.kt` | 選択場所の口コミ一覧と投稿フォーム |
| `LayeRoomTheme.kt` | 共通の配色・カード・バッジ・プルダウン |
| `UiModels.kt` | 表示モデル、固定プロンプト、サンプルデータ |
| `LayeRoomViewModel.kt` | 場所、画像読込み、フロントエンド内の操作状態 |
| `FrontendUiTest.kt` | タブ・選択・遷移・フィルター等のUIテスト |

Windows：

```bat
gradlew.bat assembleDebug testDebugUnitTest lintDebug
```

macOS / Linux：

```sh
./gradlew assembleDebug testDebugUnitTest lintDebug
```

APKビルド・Android Lint・自動テスト9件が成功しました。テストでは3タブの順序とホーム初期表示、場所名と提案カードの操作分離、写真の自動遷移・キャンセル・読込み失敗、ひろばの再選択と場所フィルター、既存の気温別コーデ、日本語投稿、アイコン描画を確認しています。

自動テストはAndroid 35相当のRobolectric環境で実行します。実機・利用者のエミュレーター固有の写真ピッカー・ランチャーの挙動は別途確認が必要です。
